# Deployment

## Standard Node / VPS

Install Node 24 and pnpm 11.25, configure PostgreSQL and runtime secrets, then run:

```sh
pnpm install --frozen-lockfile
pnpm setup
pnpm lint && pnpm typecheck && pnpm test
pnpm build
pnpm start
```

`pnpm build` also prepares public/static assets in the standalone output. `pnpm start` loads an existing .env when present and starts that standalone server; runtime environment bindings take precedence. Set PORT (or pass --port) to choose a port and APP_HOST to choose the bind address.

Run the process under a service manager with SIGTERM shutdown and restart handling. Expose the application only behind an HTTPS reverse proxy. Set BETTER_AUTH_URL and NEXT_PUBLIC_APP_URL to that exact origin before building. Do not deploy the development server. Back up PostgreSQL and restore-test it. Use a URL-encoded password in DATABASE_URL. Public production URLs must be HTTPS; ALLOW_HTTP_LOCAL_TEST exists only for isolated local production smoke tests and must never be set publicly. Sanitize forwarded client-IP headers at your trusted proxy; direct client-supplied forwarded headers are not authoritative.

## Docker VPS

`compose.prod.yml` runs database, a one-shot migration image and the standalone non-root app. It publishes no database port. App port binds to loopback for a host reverse proxy. Both Compose modes use persistent PostgreSQL/upload volumes; `down -v` destroys them. Use `docker compose down` without -v to stop safely. Health checks query the database through the app. `init: true` forwards signals and reaps children; give active AI requests time to finish/cancel during shutdown.

Production Compose intentionally requires secrets instead of default passwords. Add enabled provider environment variables explicitly under app environment (or use a reviewed `env_file`); provider keys are not build args. Optional service profiles are development conveniences, not production Redis/MinIO hardening. Never expose Mailpit, MinIO consoles or Redis publicly. SMTP from an app container uses mailpit as hostname, not localhost. Separate persistent disks and least-privilege database/S3 roles are recommended.

## Managed cloud build proxy

The session proxy's public CA must be mounted into each networked Docker build stage. The Dockerfile supports an optional BuildKit secret without persisting it in image layers:

```sh
docker build --secret id=proxy_ca,src="$CODEX_PROXY_CERT" -t modusaas:local .
```

Compose builds need an override supplying the same build secret to app and migrate. Keep the platform's Docker proxy defaults and TLS verification enabled. For provider calls inside a test container, mount the CA read-only and set NODE_EXTRA_CA_CERTS to the mounted path. Do not bake session trust material into production artifacts.

## Vercel / other Node hosting

Use a PostgreSQL provider with an appropriate connection limit/pooler, configure the same server environment and public build variables, and run migrations as a controlled release job. The application uses the Node runtime (not Edge). Local upload storage is not durable on ephemeral hosting: enable S3 or leave files disabled. Verify provider request-duration/streaming limits for AI. A Vercel live deployment has not been performed. Other Node 24 platforms can use the regular production build/start commands.

## Prisma tooling

The pinned engine-free scripts generate/apply real Prisma migrations through official npm-distributed WASM and generator packages. This avoids the native CLI engine-host download and preserves artifact integrity. The wrappers use internal APIs and are version-coupled: upgrade them with Prisma and rerun setup/build/integration tests. `pnpm db:migrate` applies committed migrations and maintains Prisma migration history; rerunning it is a no-op. For future schema changes prefer standard `pnpm exec prisma migrate dev --name feature` with binaries.prisma.sh allowed. The initial migration is committed and generated by the matching schema engine; do not regenerate it over an existing deployment. The `diff` helper is initial-bootstrap tooling only.
